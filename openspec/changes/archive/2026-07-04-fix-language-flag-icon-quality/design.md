## Context

`Assets/flags/{code}.png` are 30×20px 8-bit RGBA PNGs generated by a one-off PIL script (no SVG rasterizer available in this environment, per the `downloader-desktop` skill's flags note). `Localizer.LanguageOption.Flag` lazily loads them via `AssetLoader` at `avares://Downloader.Desktop/Assets/flags/{Code}.png`; `SettingView.axaml` displays them at a fixed 22×15 in the Language ComboBox. There are 16 flags (en, fa, es, fr, ar, eo, tr, zh, ja, hi, ru, ko, pt, de, it, az). The `fa` flag has an existing author requirement: plain green/white/red tricolor with **no emblem** (never the Sun&Lion/takbir version) — must be preserved.

## Goals / Non-Goals

**Goals:**
- Flags render crisply at the existing 22×15 display size on both standard and HiDPI (2x/3x) displays.
- Keep the exact same file paths, naming convention, and loading mechanism — this is a drop-in asset replacement.
- Preserve the `fa` no-emblem requirement and each country's correct flag mapping (en→US, pt→Brazil, ar→UAE, eo→Esperanto star, per the skill notes).

**Non-Goals:**
- No new languages/flags added.
- No change to the ComboBox layout, sizing, or the lazy-load code path.
- No introduction of a new asset pipeline/build step (e.g. SVG-to-PNG at build time) — this is a one-time regeneration, consistent with how the flags were originally produced.

## Decisions

- **Regenerate at a higher fixed raster size (e.g. 90×60, 3x the 30×20 original) rather than switching to vector (SVG) rendering.** Avalonia's `Image` control with a `Bitmap` source doesn't get free vector scaling, and introducing SVG rendering would require a new dependency/converter for one small visual fix — out of proportion to the problem. A higher-resolution raster is a strict drop-in replacement.
- **Keep PNG format and the same file names/paths.** No code changes needed in `Localizer` or `SettingView.axaml` — only the bytes of each `Assets/flags/{code}.png` file change.
- **Generation approach**: same PIL-based approach used originally (per skill notes: no SVG rasterizer on this box), scaled up in source resolution and rendered with anti-aliasing.

## Risks / Trade-offs

- [Larger PNGs slightly increase app package size] → 16 files at ~1–3 KB each even at 3x is negligible (well under 50 KB total added).
- [Manual re-creation could accidentally alter a flag's design details (e.g. re-adding the Iranian emblem, wrong shade of blue for a Nordic-style flag, wrong star count)] → Mitigation: diff each new flag against the existing PNG's visual composition (colors/stripes/proportions) before replacing, and keep the explicit `fa` no-emblem constraint front and center during regeneration; the existing `AppTests.cs:744` assertion (`Flag != null`) plus a manual screenshot check of the Settings language dropdown catches loading regressions.
