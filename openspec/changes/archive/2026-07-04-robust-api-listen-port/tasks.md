## 5. Wrap-up
- [x] 5.1 **Live end-to-end test done (author-requested), and it surfaced a real bug — now fixed.** Reserved 15151 with a raw socket, launched the real app, watched the log + `/ping` + persisted config. The app correctly failed to bind 15151 and fell back — BUT it landed on **15153, skipping 15152**, because `SingleInstanceService.LockPort` was **15152, inside the API range**: the app's own single-instance lock permanently occupied a fallback slot. **Fix:** moved `LockPort` to **15150** (outside 15151–15155). Re-ran the same live test: now the log shows `could not bind 15151` → `listening on 15152`, `/ping` returns 200 on 15152, and `config.LocalApiPort` persists 15152. Regression test `SingleInstance_lock_port_is_outside_the_api_range` guards the invariant (`LockPort` exposed as a `public const`). Extension-discovery path verified live too: probing 15151 (dead) → 15152 (200) connects — exactly what `common.js` does.
