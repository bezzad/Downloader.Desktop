## 2. View: suggestion rendering + accept key handling
- [x] 2.1 In `AddDownloadItemView.axaml`, wrapped the URL `TextBox` in a `Panel` with an overlay `TextBlock` (accent-colored, `Opacity=0.65`, `IsHitTestVisible="False"`, ellipsis-trimmed) bound to `ClipboardSuggestion` + a small bottom-right "Press Enter to use clipboard link" hint, both gated on `ShowClipboardSuggestion`. The native `PlaceholderText` is routed through a new VM `LinksPlaceholder` that blanks while the suggestion shows, so the overlay and the built-in placeholder (both render only when empty) don't collide. Added `Add_ClipboardHint` to `en.json` (other locales fall back to English).
- [x] 2.2 Added an `OnUrlBoxKeyDown` handler in `AddDownloadItemView.axaml.cs`: while `ShowClipboardSuggestion` is true, Enter or Tab calls `AcceptClipboardSuggestion()` and moves the caret to the end of the now-populated box; otherwise it falls through to normal typing (Enter/Shift+Enter insert newlines in this multi-line box). (This view had no prior KeyDown handler — the "existing" one referenced in the design was the MainWindow top-box handler, which I mirrored.)

## 3. Tests
- [x] 3.1 `Add_dialog_suggests_single_clipboard_url_and_accepts_it` — empty seed + single valid URL → `ClipboardSuggestion` set, `CanDownload` still false until accept; after accept `Urls` set + `CanDownload` true.

- [x] 3.5 **(reprocess — author-reported bug)** Enter used to just insert a newline instead of accepting the suggestion, because the multi-line `TextBox` (`AcceptsReturn="True"`) handles Enter in its own **bubble-phase** key handler which runs first and marks the event handled — so the bubble-phase `KeyDown="OnUrlBoxKeyDown"` never fired. Fixed by moving the handler to the **tunnel phase**: `UrlBox.AddHandler(KeyDownEvent, OnUrlBoxKeyDown, RoutingStrategies.Tunnel)` in the code-behind ctor (removed the XAML `KeyDown=`). New headless test `Add_dialog_enter_accepts_clipboard_suggestion_not_newline` shows the real window, focuses the box, drives a real `KeyPress(Enter)`, and asserts `Urls` == the clipboard URL with no newline.
- [x] 3.6 **(reprocess — author-reported bug: overlay flooded the dialog)** With 10+ clipboard URLs the overlay rendered the whole newline-joined list, overflowed the fixed 64px box and bled across the entire window (dark-theme screenshot). Fixed: (a) the overlay now binds a new one-line `ClipboardSuggestionDisplay` — the single URL when there's one, else an "{N} links on clipboard" summary (`Add_ClipboardMultiple` i18n key); `ClipboardSuggestion` still holds the full text that gets committed on accept. (b) Hardened the layout so it can never overflow regardless: `MaxLines="1"` on the overlay TextBlock + `ClipToBounds="True"` on the wrapping `Panel`. Test extended to assert the summary is a single line ("3 links on clipboard", no newline) while the full text is retained for accept.
